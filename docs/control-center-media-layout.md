# 媒体卡片自定义布局：实现说明

## 当前范围和清理结果

设置入口为「Hook 设置 → 媒体卡片 → 控制中心 → 自定义布局」，默认关闭。保留控制中心，以及通知/超级岛媒体按钮经 SystemUI 的 MiPlayDetailAdapter 打开的详情。当前竖屏使用全宽正方形原生封面，标题和艺术家置于封面底部，文字样式、按钮大小与内部间距、进度/时间和下方控件间距仍由原生组件提供。

停止适配应用内妙播 SDK 单独打开的 MiPlayDetailActivity。已删除 Activity 反射及生命周期 Hook、Instrumentation/Activity.onResume 回调、PluginFactory/PluginInstance 额外监听、窗口 View 树扫描和临时诊断日志；撤销仅为该入口新增的 miui.systemui.plugin 默认作用域及包加载分支调用。SystemUI 原有动态类加载器回调保留。测量 Hook 只处理已由控制中心 delegate 或通知详情工厂登记的 View，不自动接管任意同类详情。

通知详情工厂返回的根 View 没有 LayoutParams，仍等宿主加入后才登记布局。保留类型检查和空参数保护，不伪造根参数。

删除旧横屏不可达的重排、宽高估算和嵌套右列容器；目前使用独立的横屏布局和动画实现。音量栏仅在参数变化时重新赋值；设备数据变化沿用原生观察者，模块只在可用高度预算变化时额外刷新，失败释放缓存以便重试。

保留竖屏按实际宽度测量 Header、动画开始前由原生父布局定位、同次 onShown 交接和卡片本地裁剪。模糊仍从标题 View 容器上沿到封面底边：封面贡献 100%→0%，真实系统背景贡献 0%→100%，不加固定暗色。横屏装饰暂不启用。

LandscapeMediaLayout 以实际内容宽高建立左侧正方形封面、右侧原生 Header 和设备列表；panel 不写外框宽高。现在在 startShow/startHide 锁定布局前解析父约束及自定义终点，动画期间保持同一层级，不再到 onShown 才切换结构。方向/原生布局回调按嵌套深度还原并重新采集参数。空间不足保持原生布局。本轮交付未签名 Release，不运行旧试验测试或额外 APK 检查。

LandscapeMediaPanelTransition 接管与旧两列结构冲突的媒体几何路径，不在原生 frameCallback 后修正坐标。保留原生 spring、大小/字体进度、alphaDeviceIcon、alphaProgress、背景材质/圆角以及完成/取消生命周期；API 102 非虚调用原生父类 frameCallback，API 101 按已反编译父类实现释放调度标志。以卡片为共同坐标系采集小卡片及新布局矩形，每帧转换到实际父节点。列表和进度等内部保持完整测量尺寸，使用同一插值矩形缩放与渐显。终帧和静态界面共用端点；反向动画保留同代端点，原生配置事务使旧代失效。

通知/超级岛 MiPlay 普通详情在横屏仍为纵向根容器，不能要求它先变为 SupportLand。仅已登记的 ModalQSControlDetail 使用 MiPlayLandscapeSizing：采用插件横屏内容宽度、原生横屏 Header 高度并限于当前窗口配置可用区域，调整真实模态容器及其内容链；其余控件复用同一横屏布局。保存并在方向更新前恢复原宽高/weight/方向，原生 updateContainerHeight 后重申横屏宿主尺寸。此分支不作用于 panel，也不接入特殊 SDK Activity。

动画中的 ImageView 叶节点通过 layout/setFrame 更新尺寸，不能只逐边写 left/top/right/bottom：ImageView 在 setFrame 中重算 CENTER_CROP/FIT_CENTER 的绘制矩阵。旧实现保留大封面的矩阵，在小边界内只露出左上角；按钮内部图标也可能在最终原生布局刷新矩阵时跳动。父容器仍仅写动画边界，不触发被 suppressLayout 锁定的层级重排。

横屏重排前先按插件原生单列 Header 宽度测量动作行，再固定其原生测量宽度。MiPlay 的纵向 Header 随新外框变宽，其 MATCH_CONSTRAINT 动作行宽度不能作为右列最小宽度，否则会错误拒绝两列布局，表现为只有背景变宽、内容仍保持纵向。

艺术家与动作按钮之间的留白不是动作行的 topMargin：原生文字从上向下排、动作行从下向上定位，实际空隙由两组约束共同产生。NativeMediaActionSpacing 在原生层级/参数还原后按单列宽度测量、布局，记录各文字容器底边和音频/视频动作行顶边；重排时显式使用两者的净距离，原有上/下边距已包含在坐标内，不重复累加。横竖屏、Panel 和通知 MiPlay 共用此计算；竖屏高度预算同时预留该留白，其他组件间距、封面边距和动画规则不变。

panel 静态交接同时检查原生动画的 isExpanded 状态；横屏动画终点与静态子布局一致。右列进度、音量、设备间距取原生竖向配置资源，避免继承横屏左栏用于预留位置的较大空白。设备余量不足一整行时仍应用并允许列表滚动；只有固定控制组本身放不下时回退。

收尾清理移除初始化、入口接入、等待/拒绝/应用布局的调试日志及相关字符串状态，仅保留安装失败、布局异常、模糊不可用等错误/降级日志。MediaLayoutParams 统一横竖屏原生参数复制和约束重建，相同约束不再重复提交；动画端点捕获收敛为共用路径，每帧复用节点矩形及父节点索引，减少临时 Map/RectF 分配，不更改插值或界面参数。

无媒体会话时，系统会清空 ImageView.drawable，但占位图仍在 background。模糊条件改为任一内容存在即可启用；setCover 完成后重新同步，使占位背景也进入相同的标题区域到封面底边过渡。

## 反编译依据

- MediaPanelDelegate.initView 按 forceVertical/折叠设备条件选择普通或 SupportLand 详情，不能仅根据屏幕方向判断结构。
- SupportLand.resetByOrientation 会重设根容器方向、重置高度、调用 resetUILayout、更新设备高度，再调用 Header.onOrientationChanged。resetUILayout 重写 Header 和 Recycler 的尺寸、margin、padding。
- MediaPanelAnimator.calculateViewValues 记录 Header、metadata、封面、文字、动作、进度、音量、分隔线和列表的端点；其缓存只比较部分位置。
- frameCallback 横屏分支直接用 Header 宽度和分隔线宽度推算列表 left/scale，并按 Header 宽度缩放进度和音量。换父容器后，原生公式不再匹配。
- frameCallback 还调用父类回调、更新背景/圆角、文字指标和设备按钮透明度，不能为了改几何而跳过全部职责。

## 横屏目标和空间规则

外框宽 W、高 H、位置、圆角、背景材质使用系统本次原生测量结果，不从竖屏宽度或屏幕尺寸猜测，不扩大外框。

左侧为 1:1 原生封面，左、上、下留与原生标题容器顶部 padding 相同的空白（当前系统资源为 16dp），边长为原生内容可用高度减去两倍该边距；封面 CENTER_CROP。左侧列仍预留原来的 H×H 空间，不改右列起点；封面 LayoutParams 同时保留四侧 margin，使原生 WRAP_CONTENT 测量不会随着封面缩小而压缩背景容器。Panel 和通知 MiPlay 共用此规则；Panel 动画捕获该实际终点，展开、收起及反向动画无需另一份固定尺寸或帧尾校正。右侧与竖屏一致，从上到下为标题、艺术家、动作按钮、进度/时间、音量、设备列表。标题/艺术家间距、进度/音量/设备间距及列表上下 padding 均使用竖向配置的原生值；进度和时间保持同一原生容器。分隔线保留对象和 ID，但在自定义结构中隐藏且不占空间。所有媒体控件使用原生 View，不复制另一份标题、按钮或 Recycler。

静态横屏不再把 Header 搬入新父容器：反编译确认 QSControlMiPlayDetailHeader.onDetachedFromWindow 会清空 cover 并设置 hasCover=false。Header 和 Recycler 现在留在原父节点，只有封面从 metadata 移到左侧；对已登记且处于静态横屏的原生根 LinearLayout 接管 onLayout，将 Header 和设备列表纵向定位在右侧。测量时列表不额外占第三个横向槽位。还原时不摘下 Header，不触发封面清理，也无需等待播放状态或曲目变化来重新推送封面。

固定控制组保持原生字号、尺寸和间距，设备 Recycler 使用剩余高度并内部滚动，不再外套 ScrollView。若原生外框不能同时容纳封面、右列最小宽度和基本控制组，该尺寸回退原生横屏，避免扩大背景或压缩字体。先完成基础布局和动画，横屏模糊后续单独考虑。

## 实施顺序

### 1. 原生快照与状态管理

建立 NativeLayoutSnapshot，记录实际父节点、序号、按类型复制的 LayoutParams、padding 和模块要改动的 visibility/clip。快照在还原自定义结构、系统完成本方向原生重置后获取，不引用已经改动的参数，不跨方向复用启动时快照。

整理原生/竖屏/横屏及动画状态。原生配置回调嵌套时，用深度控制一次还原、一次重新应用；只在最外层结束后提交。DPI、主题、字体或配置导致内容重建时，释放旧视图状态并重新绑定。

验收：原生 W/H 有唯一来源，竖→原生横→竖可正确恢复，层级无重复和旧参数。

### 2. 横屏静态布局

独立 LandscapeMediaLayout，输入原生内容边界与快照，输出各 View 在实际父节点内的目标矩形和设备高度预算。CoverParent 位于左侧；移除封面后的原 Header 与设备列表组成右列。只创建必要布局容器，保存所有原生 View 的原父节点和序号。

PortraitMediaLayout 保持竖屏职责。横屏不使用竖屏增高和解除外框限制逻辑。先测固定控制组，再把剩余空间给 Recycler；设备数量改变只影响列表预算。TV 控制区仍保留功能，空间不足执行回退。

验收：直接横屏打开比例正确，至少一个可用设备项完整显示，多设备可滚动；字体、按钮与进度/时间原生关系不变。

### 3. 匹配新结构的动画几何

复用原生 size、position、字体、alphaDeviceIcon、alphaProgress 等进度和完成/取消流程。独立横屏几何路径与静态布局共享目标矩形，将来源小卡片坐标转换到各实际父容器再插值。

按反编译结果分离通用生命周期/材质/文字行为和旧横屏几何，只替换冲突的几何分支。禁止先执行旧几何再在帧尾补 left/top，禁止粗暴跳过整个 frameCallback。若 ROM 的方法结构无法可靠分离，该版本回退原生横屏。

卡片、背景、裁剪使用同一动画矩形；音量和设备沿用原生渐显；设备切换按钮沿用原生显隐。p=1 的插值矩形必须等于静态矩形。取消和反向动画接续当前进度。

验收：展开/收起/快速反向都无越框、按钮闪现、终帧跳动。

### 4. 横竖屏切换

交接当前动画，恢复原生层级，让系统完成方向重置，然后读取新边界、快照和目标；清除旧方向动画端点和设备预算，在首个有效绘制前完成重新绑定，不延迟一帧校正。

分别处理普通详情和 SupportLand；遵循 forceVertical、宽折叠屏等原生模式，不把所有横向屏幕视作两列。

验收：打开时、展开中、收起中、连续旋转均无旧父节点、旧尺寸、旧裁剪或旧动画缓存；回到竖屏保持当前模糊与文字样式。

### 5. 分阶段手机验收与交付

先静态横屏，再展开/收起，最后旋转和中断。覆盖控制中心及已保留的通知/超级岛详情入口，特殊 SDK Activity 不在范围。检查有/无封面、长标题、暂停/播放、设备数量、系统字级、TV 控制区和 RTL。

实现阶段按要求交付未签名 Release。桌面编译只证明可构建，实际动画和系统材质以手机结果为准。
